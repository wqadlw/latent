## 一、后端约定

### 1.1 鉴权是单点挂载，不要逐个路由加

除 `/api/auth/*` 与 `/api/meta` 外，**所有路由必须挂登录守卫**。挂载点在 `app/main.py`：

```python
_PROTECTED_ROUTERS = [...]                       # 路由模块清单
app.include_router(mod.router, dependencies=[Depends(get_current_user)])
```

新增路由模块**忘了加进 `_PROTECTED_ROUTERS`**，`tests/test_auth_api.py::test_every_business_router_is_guarded`
会失败 —— 这是刻意的护栏。

⚠️ **不要**去 20 个业务路由文件里逐个加鉴权依赖，那是刻意设计的单点挂载。

### 1.2 敏感字段靠列类型加密，不要在路由里手写

- 需要落库加密的字段，列类型用 `app.crypto.EncryptedText`。
- 密文前缀 `enc:v1:`；**无前缀视为历史明文，读取时原样返回**（保证老库可用）。
- 密钥：`APP_SECRET_KEY`（JWT）/ `APP_FERNET_KEY`（字段加密），缺省自动落盘 `backend/data/`。
- ⚠️ **更换 Fernet 密钥 = 已加密数据永久无法解密**。

### 1.3 schema 变更必须走 Alembic

- 迁移目录 `backend/alembic/versions/`。**不要再往 `init_db()` 里加 PRAGMA / ALTER TABLE。**
- 存量数据刷写放 `app/datamigrate.py`，且**必须幂等**。
- 生成迁移：

```bash
cd backend && venv/Scripts/python.exe -m alembic revision --autogenerate -m "说明"
```

### 1.4 ⚠️ 外键列不要写 `default=0`

`app/database.py:43` 开着 `PRAGMA foreign_keys=ON`，而 `0` 通常**不是**合法外键
（`persona` 表里就没有 id=0）。正确写法是 `default=None`。

**真实事故**：`models.py` 的 `Account.platform_id` / `persona_id` 曾是 `default=0`，导致
**「新建账号不选人设」必然 500**（`FOREIGN KEY constraint failed`）。D5 发现并修复。

**护栏**：`tests/test_account_api.py::test_no_foreign_key_column_has_scalar_default`
遍历 `Base.metadata` 断言「外键列不得有标量默认值」，拦住同类缺陷在别的表重演。

### 1.5 版本号唯一来源

`backend/app/version.py`，前端经 `/api/meta` 读取。**不要再在别处硬编码版本号。**

### 1.6 代码风格

- `ruff check .` 必须 **0 告警**（配置见 `pyproject.toml`）。
- ⚠️ **不要开启 ruff 的 `UP` 规则集**：项目要兼容 Python 3.9，`dict[str, X]` 作为运行时注解需要
  `from __future__ import annotations` 或 3.10+。开 `UP` 会强迫全仓改成 3.10+ 语法，反而破坏兼容性。
- 新增内置变量时需同步维护 `app/constants.py` 的 `BUILTIN_VARIABLES` 与 `SUPPORTED_RENDER_VARIABLES`。

### 1.7 ⚠️ API 响应信封：业务文案在顶层 `msg`

拦截器做 `(response) => response.data`，所以调用方拿到的 `res` **就是** `{code, msg, data}`。

- 业务文案在**顶层 `msg`**；`data` 只放业务负载。
- ⚠️ 读成 `res.data.msg` **不会报错**，只会弹一个**没有文字的绿色 toast**。
  D6 踩过一次（`POST /prompt-library/import`）。**同一模块内取值方式必须一致。**

## 二、生产流水线 / 队列（Phase C）

### 2.1 规格是数据，不是代码

九步流程的顺序 / 开关 / 续跑规则都在 `app/services/pipeline.py`，**不要**再写回 `orchestrate_run`
的函数体。规格存在 `production_task.pipeline_spec`（JSON 文本，**故意不拆列** —— 字段还会变）。

### 2.2 三条不可违背的语义

1. **只跳连续前缀** —— ③ 完成但 ② 未完成时，**不得跳过 ③**。
2. **`done` ≠ 产物可用** —— 行标 done 但产物列为空，**必须重跑**。
3. **`connect` 不阻塞** —— 它无产物且每次都要重开浏览器；算作未完成会让全部产物复用失效。
   故 `starts_at`（执行器第一步）与 `next_key`（第一个需真重生成的步骤）是**故意分开**的。

### 2.3 两个 status 必须分开

`production_task.status`（内容进度）与 `pipeline_job.status`（调度）**必须分开**。

- `enqueue` 重投时**复用同一 job 行**（原地重置），否则批次进度会把运行数算多。
- `execute_job` 必须**回查 run 终态**：`orchestrate_run` 正常返回 ≠ 成功 —— 它会把失败写进
  `run.status` 就返回。终态白名单：
  `_TERMINAL_OK = ("await_confirm", "confirmed", "succeeded", "published")`。

### 2.4 取消与过审

- **取消语义保守**：排队中立即取消；执行中**跑完当前尝试**再标取消（LLM / 浏览器步骤是原子的）。
- **批量刻意不批量过审**：一律停在 `await_confirm`，**不留绕过开关**（产品决策，不是遗漏）。

### 2.5 并发

- 并发上限 `PIPELINE_CONCURRENCY`（默认 2）。
- `APP_PIPELINE_WORKER=0` 关闭调度线程（测试用，见 `conftest.py`）。

## 三、前端结构（Phase D 起）

### 3.1 公共层

- **`src/utils/`** 纯函数：`clipboard.js`、`markdown.js`、`format.js`（日期时间）、
  `download.js`（Blob 下载）、`lookup.ts`（`nameById` / `findInCategoryMap`）、`json.ts`（`safeJsonParse`）。
  ⚠️ `lookup` 与 `json` 已在 D3 迁到 **`.ts`** —— 别照着旧笔记找 `.js`。
- **`src/constants/`** 纯数据 / 标签映射：`platforms.js`（平台码单一来源）、`status.js`（状态枚举 +
  取值函数 + `KEYWORD_TYPE_LABEL/TAG/OPTIONS`、`TOPIC_STATUS_SHORT`）、`modes.js`、`icons.js`
  （**图标单一真源** `ICON_MAP/ICON_OPTIONS/iconOf`）、`browserStudio.js`、`production.js`、
  `prompts.js`、`menu.js`（菜单派生，见 §四）。
- ⚠️ **图标下拉别再手写数组**（D5 前 Knowledge 8 项 / Keyword 9 项，已经漂移过）。
- ⚠️ **Element Plus 图标是全局注册的**（`main.js` 里全量 `app.component()`）→ 模板里写
  `<Memo />` **不 import 也能用**。静态检查工具不知道这点，会把「用了没导入的组件」**误报**成孤儿
  —— `_orphan-scan.py` 就为此踩过假绿坑，改它之后要用故意注入的错误文件重验。

### 3.2 视图职责

- **视图只做布局与数据编排，展示交给子组件。**
- **没有第二个调用方就不抽 composable** —— 强行合会变成「靠 6 个 props 切换形态」的组件。
- **禁止在视图里新写**：日期格式化、Blob 下载、「列表按 id 找名称」、状态 / 标签映射。

### 3.3 ⚠️ 日期：不要用 `new Date()` 解析后端时间

`create_time` 是 naive DateTime，序列化成 `2026-10-11T11:30:00`（**无时区**）。
取本地「今天」必须用 `toDateKey()`，**不要用 `toISOString().slice(0,10)`**
（那是 UTC 日期，东八区下午 4 点后会差一天）。

### 3.4 剪贴板只有一个实现

`src/utils/clipboard.js`，**禁止再写 `navigator.clipboard.writeText`**。

- `writeClipboard(text)` —— 原语，静默，返回 boolean
- `copyText(text, label)` —— 写 + 统一提示

⚠️ **必须保留非安全上下文降级**：内网 IP（`http://192.168.x.x`）下 `navigator.clipboard`
为 `undefined`，没有 textarea + `execCommand` 回退就会**静默失效**。

### 3.5 `production_task.status` 是两套模式的并集

手动：`draft/processing/done/archived`
自动：`created/running/await_confirm/confirmed/succeeded/partial/failed/published/cancelled`

它**同时也是浏览器工作室的「运行状态」** —— 同一个 DB 列，**不要建第二份文案表**。
唯一来源是 `constants/status.js` 的 `TASK_STATUS_LABEL/TYPE`。

⚠️ **状态色值归 CSS**（`.st-draft` 负责色带），不要在 JS 里再存 `color`。

### 3.6 子组件边界

- `browser-studio/`（D4）子组件**不改运行状态、不轮询**，只 `emit` 意图；请求与轮询留在壳。
- 弹窗**自取自己的数据**。
- **条目级动作归面板，弹窗级动作归壳**（D5）：面板自己发删除 / 批量 / 排序请求，成功后
  `emit('changed')` 让壳重拉；「打开哪个弹窗」由壳编排（弹窗 `defineExpose({ open… })`，
  保存成功 `emit('saved')`）。

### 3.7 拆分产物目录

```
views/browser-studio/     RunListPanel RunDetailPanel CreateRunDialog PrecheckDialog RewriteDialog + studio-shared.css
views/knowledge/          CategoryPanel ItemPanel KnowledgeDetailDrawer
                          KnowledgeItemDialog CategoryDialog BatchImportDialog + knowledge-shared.css + shared.js
views/keyword/            GroupPanel KeywordItemPanel TopicPool MatrixView
                          + GroupDialog KeywordDialog TopicDialog BatchImportDialog ImportPromptBanner
                          + keyword-shared.css
views/production/steps/   StepIndustry StepPersona StepPlatform StepDemand StepOutline
                          StepIllustration Step5 StepFinal + step-shared.css
views/prompt-library/     PromptCard PromptEditorDialog PromptViewDrawer PromptImportDialog PromptAiDialog
                          + prompt-library-shared.css
components/layout/        WorkbenchLayout.vue
```

配套的 `composables/production/*`、`constants/{production,prompts,menu}.js` 在各自目录。
逐包文件清单与决策见 `docs/PhaseD-*.md`。

### 3.8 共享样式表（`*-shared.css`）

- **非 scoped** —— scoped 够不到子组件内部，用 `:deep()` 会把父子重新耦合 = **假拆分**。
- **门槛**：某个类 **≥2 个组件**用到才放进共享表；只被一个组件用的留在它的 scoped 块。
  共享表**不是杂物间**。
- ⚠️ **必须加视图前缀**（`kb-` / `kw-`）。Knowledge 与 Keyword 共用大量类名
  （`.panel-head` / `.item-panel` / `.batch-bar` / `.head-left`），照原名会**泄漏到另一个视图**。
  `.kw-layout` 两边都用（220px vs 232px）→ 只能留在各自壳的 scoped style 里。
  写完用脚本比对全站类名一遍（`.var-panel` / `.view-content` 这类通用名最易撞）。
- ⚠️ **每个用到该表的子组件都要自己 import**（CSS 一旦被任一组件 import 即全局生效，
  所以验收只能发现「整张表没被加载」，发现不了「某个组件忘了 import」）。
- ⚠️ **面板类名同时是验收脚本的钩子**：`.group-panel` / `.item-panel` / `.prompt-item` 被
  `shot-*.mjs` 依赖。拆组件时**保留旧类名**，验收基线才能原样比对。
- **scoped 样式只作用于子组件的根元素**。子组件根是 `el-dialog` / `el-drawer` 时父组件一定够不到
  其内部 —— 样式要**跟着标记搬进子组件**。

### 3.9 ⚠️ 自适应列宽卡片里的操作行必须允许换行

卡片是 `minmax(300px, 1fr)`。窄列装不下按钮时，只有 `justify-content: flex-end` 会让整行
**向左溢出卡片**，第一个按钮跑到侧边栏底下被盖住 —— **用户点不到，页面却无任何报错**。

`flex-wrap: wrap` 是修复（见 `prompt-library-shared.css` 注释）。

## 四、菜单与工作台布局（D7 起）

### 4.1 菜单单一来源 = 路由 `meta`

- 派生逻辑：`src/constants/menu.js` 的 `buildMenuGroups(routes)`。
- 消费点：`Layout.vue` 的 `computed(() => buildMenuGroups(router.getRoutes()))`。

**改菜单请改 `src/router/index.js`**：

| `meta` 字段 | 作用 |
|---|---|
| `title` | 菜单文案（缺失时回落到路径，**不产出空标题**） |
| `group` | 分组，**首次出现即建组** |
| `icon` | 图标名 |
| `badge` | 仅菜单用的小徽标 |
| `hidden` | 排除出菜单（404 兜底页） |

- **路由声明顺序 = 菜单顺序**（组顺序与项顺序都是）。
- 无 `meta.group` 的（登录页、Layout 壳 `/`）**自动不进菜单**；带 `:` 的通配路径也自动排除。
- `Layout.vue` **不再持有任何菜单文案字面量**。
- `router.getRoutes()` 返回**扁平**列表，且子路由 `path` **已是全路径** —— 无需父子拼接。

### 4.2 `smoke.mjs` 有覆盖度护栏

`assertSmokeCoversMenu()` 抓侧边栏 `.nav-item` 的 href，凡不在 ROUTES 清单里的即 **exit 1**。

**加路由必须同步加进 ROUTES**，否则冒烟会出现静默盲区（历史上少测 4 条：19 vs 23）。

### 4.3 两栏容器 `WorkbenchLayout.vue`

`components/layout/WorkbenchLayout.vue`

- props：`asideWidth`(280px) / `gap`(16px) / `align` / `fill` / `minHeight` /
  `collapsed`（**已实现但未接任何页面** —— 接了就是功能变更，不是重构）
- slot：`aside` / `main` / `detail`（**预留，当前无消费者**）
- 根元素**就是** grid 容器，所以调用方类名（`.prod-layout` 等）会 fall-through 成属性，
  **旧的验收钩子照旧有效**。

### 4.4 ⚠️ 槽位包裹元素必须 `display: contents`

它不生成盒子，消费方元素仍是**直接的 grid item**，与重构前**逐字节等价**。

换成普通块级盒子后，没有 `height: 100%` 的子元素（`.task-panel` / `.iq-side`）会
**静默塌成内容高，而栏宽照常正确** —— 所以「只断言栏宽」**抓不到**。

护栏必须**同时**断言 `wrapperDisplay === 'contents'` 与 `asideHeight ≈ containerHeight`。

### 4.5 ⚠️ 列宽用 `minmax(0, 1fr)`，不要用 `1fr`

`1fr` 隐含 `minmax(auto, 1fr)` —— 内容比列宽时列**不肯收缩**，会把整个容器顶宽。
断点统一 `max-width: 1024px` 收成单列。

生产页 gap 由 20px 归一为 16px（**有意为之**）。

## 五、TypeScript（D3 起，渐进式）

- **存量 `.js` / `.vue` 不参与类型检查**（`allowJs: true` + `checkJs: false`）。
  新文件写 `lang="ts"`。**不要**为了「让 typecheck 全绿」去给存量文件加类型或降级配置。
- ⚠️ **不要加 `declare module '*.vue'` 兜底**：它会让每个 `.vue` 导入退化成
  `DefineComponent<{},{},any>`，props 全变 `any`、传错 prop 不报错 —— 把 TS 的收益全部抵消。
  vue-tsc 原生解析 `.vue`。
- ⚠️ **`typescript` 必须钉 `^5.9`**。TS 7（Go 原生编译器）删掉了 vue-tsc 依赖的 `./lib/tsc`
  子路径，装上直接 `ERR_PACKAGE_PATH_NOT_EXPORTED`。**这个坑搜不到，别升。**
- **`typecheck` 不进 `npm run build`**：构建产物是后端打包 exe 的输入，不能被存量类型瑕疵阻塞。
- 文件从 `.js` 改名为 `.ts` 时，**调用方 import 路径不用改**（Vite 按扩展名解析）。
  已迁移范例：`utils/lookup.ts`。
- `tsconfig.json` 的 `paths` 里 `@/*` 只是让 TS 认识别名，**真源是 `vite.config.js` 的
  `resolve.alias`** —— 改一处要同步另一处。

## 七、环境与网络

- Python venv：`backend/venv`（3.13.14）。依赖：
  `backend/venv/Scripts/python.exe -m pip install -r requirements.txt -r requirements-dev.txt`
- 启动：`cd backend && APP_NO_BROWSER=1 ./venv/Scripts/python.exe run.py`
  端口默认 8765（`APP_PORT` 可覆盖）；`APP_DB_PATH` 指定数据库（测试靠它隔离）。
- 前端构建：`cd frontend && npm run build`（产物输出到 `backend/static/`）。
- 前端门禁：`npm run typecheck`、`npm run audit:tokens`、`node scripts/smoke.mjs`。
- ⚠️ **网络约 40KB/s**，pip / npm 安装耗时长，尽量后台跑并重定向到日志文件。
  **不要用 `| tail` 包裹 `pip install`**（会收到 SIGTERM），用 `> log 2>&1`。
- ⚠️ **npm 的 proxy 配置指向已失效端口 7897**。装包要显式覆盖：

```bash
npm_config_proxy=http://127.0.0.1:59303 npm_config_https_proxy=http://127.0.0.1:59303 npm install ...
```

- `npm install` 首次可能因 esbuild postinstall `EBUSY` 失败，**重试即可**。
- Windows GBK 区域：`.ini` 配置文件**必须纯 ASCII**（configparser 按区域编码读，中文注释会崩）。
- 系统 curl 走代理，本地回环请求需 `--noproxy '*'` 或 httpx `trust_env=False`。
- ⚠️ **`D:/AAA/GEO` 不是 git 仓库**，没有版本控制兜底。批量改动前自己确认可回滚，
  **不要依赖 `git checkout` 还原**（会失败，然后你可能以为它成功了）。
