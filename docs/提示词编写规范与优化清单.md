# 多行业提示词矩阵管理系统 · AI 提示词编写规范与优化清单

> 适用范围：本系统的「AI 提示词库」（4 分类：大纲 / 初稿 / 洗稿 / 安全）及软文生产流程。
> 目的：让团队成员写出**可被系统正确渲染、且产出质量稳定**的标准提示词，并统一规范。

---

## 一、核心机制（必须先懂）

本系统的提示词是**带变量占位符的模板**。运行时，引擎（`prompt_engine`）会把 `{变量名}` 替换成真实上下文（行业、平台、人设、品牌、关键词、知识库、上一步产物、规则等）。

**最关键的铁律**：模板里只能使用系统**白名单变量**（见第三节）。写了白名单之外的变量，渲染时会被**原原样保留成 `{变量名}` 字面文本**喂给 AI，且**不报错**——这会悄悄污染输入、拉低产出质量，极难排查。

> 系统已内置两道防护：
> 1. 编辑提示词时，检测到的变量若不在白名单，会以**红色告警条**提示，保存时二次确认。
> 2. 渲染（库内预览 / 生产生成）接口会返回 `unresolved` 列表，前端对未解析变量弹提醒。

---

## 二、标准四段式写法

任何一条提示词都推荐遵循：

```
# 角色（Role）
你是一位……（明确身份与专业领域）

# 背景（Context，全部用 {变量} 注入，不要硬编码）
行业：{industry_name}
平台：{platform_name}（合规等级 {compliance_level}）
人设：{persona_name} —— {persona_identity}，语气：{persona_tone}
品牌：{brand_info}
知识：{knowledge_content}

# 任务（Task）
围绕关键词 {keywords}，生成/改写/审核……（明确要做什么）

# 约束与输出格式（Constraints & Format）
- 字数 {word_min}-{word_max}
- 必须遵守规则：{compliance_rules} / {anti_ai_rules} / {ai_seo_rules}
- 输出格式：……（给明确结构，便于后续解析）
- 不要输出思考过程 / 修改说明
```

**要点**
- 角色要具体（"5 年经验的护肤博主" 优于 "专家"）。
- 背景全部用变量，禁止把行业名/品牌名写死（否则换行业就废了）。
- 务必加一句 **"不要输出思考过程 / 修改说明"**，减少废话 token。
- 给**输出格式**（分隔符、字段名），方便下一步或机解析。

## 四、四类提示词写法范式

### 1. 大纲类（outline）
目标：确定结构 + 埋入品牌与关键词点，不直接硬塞。
```
# 角色
你是一位资深的 {industry_name} 行业内容策划。
# 任务
围绕关键词 {keywords}，结合知识库 {knowledge_content}，产出 3-5 段文章大纲。
# 要求
- 每段标注写作要点与字数分配（总字数 {word_min}-{word_max}）
- 品牌 {brand_name} 自然融入不少于 2 处，不堆砌
- 契合 {platform_name} 平台调性：{platform_tone}
# 输出
直接输出大纲，不输出思考过程。
```

### 2. 初稿类（draft）
目标：基于大纲写完整初稿，锁定人设语气，注入规则。
```
# 角色
以 {persona_name}（{persona_identity}）的身份、采用 {persona_tone} 语气撰写。
# 背景
品牌：{brand_info}
大纲：{outline_content}
关键词：{keywords}（密度 3-5 次，长尾自然分布）
# 规则
去 AI 味：{anti_ai_rules}
合规：{compliance_rules}
# 输出
字数 {word_min}-{word_max}；小标题分段、每段≤300 字；关键数据加粗；
禁止第一人称"我们公司"，禁止出现竞品名称；直接输出正文。
```

### 3. 洗稿类（rewrite）
目标：去 AI 味精修，保品牌词密度，增加真实感。
```
# 任务
对原文 {draft_content} 去 AI 味精修。
# 要求
- 增加口语表达、具体数据、场景细节、个人感受
- 按 AI SEO 规则 {ai_seo_rules} 确保品牌词 {brand_name} 密度 3-5%
- 品牌名/官网/联系方式自然露出；保持核心信息不变；字数 {word_min}-{word_max}
# 输出
直接输出精修稿，不输出修改说明。
```

### 4. 安全类（safety）
目标：合规检测 + 结构化报告，便于后续解析。
```
# 任务
审核 {rewrite_content}。
# 检测要点
违禁词（广告法极限词）/ 硬广占比(≤20%) / 品牌露出完整性 / 关键词覆盖率(≥70%)
# 输出格式
===最终文章===
（优化后正文）
===安全报告===
- 违禁词：通过/不通过
- 硬广占比：xx%
- 品牌露出：完整/缺失
- 关键词覆盖率：xx%
```

## 五、通用最佳实践

1. **角色具体**：给身份、经验、口吻，而非泛泛"你是一个 AI"。
2. **背景变量化**：所有行业/品牌/平台相关字段用 `{变量}`，别写死。
3. **约束可量化**：字数区间、密度百分比、段落数——越具体越好。
4. **给示例（few-shot）**：复杂格式附 1 个例子，模型遵循度大幅提升。
5. **明确禁区**：禁止第一人称公司、禁止竞品、禁止极限词。
6. **指定输出分隔符**：如 `===最终文章===`，方便下游解析。
7. **控制段落长度**：每段 ≤300 字，移动端阅读友好。
8. **善用规则库**：`{anti_ai_rules}/{compliance_rules}/{ai_seo_rules}` 由系统按行业注入，务必引用。

## 六、系统优化清单（已实现 / 待办）

### ✅ 本轮已实现（P0）
- **变量未解析校验**：编辑时非白名单变量红色告警条 + 保存二次确认；渲染接口返回 `unresolved`。
- **`platform_tone` 修复**：原先恒为空，现从平台 `config`（marketing + features）自动派生，真正可用。
- **自定义变量生效**：库内预览与生产渲染均支持 `custom_vars` 注入；生产流程含自定义变量时弹窗填值。

### 📋 待办（P1 / P2，后续可排期）
- **P1 版本历史/回滚**：提示词反复改，应存快照支持对比回滚。
- **P1 效果归因**：生产各步记录所用 `prompt_id`，统计哪条提示词产出采纳率/评分最高。
- **P1 测试渲染 UI 化**：编辑页"试运行"tab 填 sample 值直接看渲染。
- **P2 跨行业复用/平台级模板**：支持从官方模板库克隆、按平台继承。
- **P2 条件空段落**：渲染时空值产生 `品牌信息：\n`，可支持 `{?brand_info}…{/brand_info}` 条件块或 trim 空行。

## 七、给「其他 AI」的元提示词（Meta-Prompt）

> 当你想借助 ChatGPT / Claude / 通义等其它 AI **帮你起草一条符合本系统规范的标准提示词**时，
> 把下面这段直接发给它即可。它产出的结果可直接粘贴进本系统提示词库（记得确认变量名在白名单内）。

```
你是一名「多行业提示词矩阵管理系统」的资深提示词工程师，擅长把模糊的营销需求，转化为该系统可稳定渲染、产出质量高的标准提示词模板。

# 你的任务
为系统「AI 提示词库」编写一条标准提示词模板（带 {变量} 占位符）。这条模板最终会被系统引擎渲染成真正发给大模型的提示词，请直接产出"可粘贴即用"的成品，不要给我一段需要我再加工的描述。

# 系统约束（必须严格遵守）
1. 系统是"模板引擎"：运行时用真实上下文替换 {变量名}。模板里只能写占位符，绝不能把具体行业名 / 品牌名 / 平台名写死，否则换行业就废了。
2. 只能用下方白名单变量（大小写敏感）。写了白名单外的变量，渲染时会被原样保留成 {xxx} 字面文本喂给 AI——不报错，但会污染输入、拉低质量，极难排查。
   - 行业/平台：industry_name, industry_desc, platform_name, compliance_level, platform_tone, word_min, word_max, current_date
   - 账号/人设：account_name, account_content_track, persona_name, persona_identity, persona_tone, persona_contact_rule
   - 品牌：brand_name, brand_info, brand_selling_points, brand_official_url, contact_phone, contact_wechat, contact_email, brand_slogan, core_products, target_keywords, brand_story
   - 关键词/知识：keywords, keyword_list, knowledge_content, knowledge_items, knowledge_summary, knowledge_titles, knowledge_count
   - 生产产物：outline_content, draft_content, rewrite_content
   - 规则：anti_ai_rules, compliance_rules, ai_seo_rules
3. 自定义变量：若白名单不够用，可在模板中自定义 {自定义变量名}，并在【自定义变量说明】里写清含义与建议取值——系统渲染前会弹窗让用户填写，不影响渲染。

# 标准四段式结构（强制遵循）
# 角色(Role)：给具体身份 / 经验 / 口吻（如"5 年经验的护肤博主"），避免泛泛的"你是一个 AI"。
# 背景(Context)：全部用 {变量} 注入——行业、平台、人设、品牌、知识、规则各取所需，禁止出现真实名称。
# 任务(Task)：明确做什么、围绕哪些关键词、产出什么形态（如"3-5 段大纲/完整初稿/精修稿/安全报告"）。
# 约束与输出格式(Constraints)：量化约束（字数区间、品牌词密度 %、段落数）；给明确输出分隔符或字段名，方便下游解析；末尾固定加一句"不要输出思考过程或修改说明。"。

# 我提供的信息
- 类型（四选一）：大纲类(outline) / 初稿类(draft) / 洗稿类(rewrite) / 安全类(safety)
- 行业示例：<在此填写，如 美妆护肤>
- 平台示例：<在此填写，如 小红书>
- 额外要求：<在此填写，如 增加 FAQ 模块、强调成分安全、加入真实使用场景>

# 输出格式（严格按序输出，不要替我执行任何文章生成）
1. 【模板正文】——上面要求的四段式，可直接粘贴进系统提示词库（变量用 {变量名}，行内引用规则用 {anti_ai_rules} 等）。
2. 【所用变量清单】——逐条列出本模板用到的 {变量名} 及其作用，并自查确认全部在白名单内；若有自定义变量一并标注。
3. 【编写说明】——简述角色 / 约束 / 输出格式的设计理由，便于我二次调整。
4. 【自定义变量说明】（如用到）——列出自定义变量名、含义、建议取值。
```
